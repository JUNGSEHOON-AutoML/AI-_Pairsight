# 사람이 작성하는 실험 지침 — 초안

**현재 상태: 실행 금지. 이번 작업은 틀만 구현했다.** 새 dev/holdout 사례가 비어 있어 실행 가드가 거부한다. 자료 확보와 사람의 별도 실행 지시 전에는 루프를 켜지 않는다.

## 목표와 변경 범위

실제 사진의 오판 없이 확정 가능한 판정을 늘린다. 후보 생성자는 저장소의 `tuning/thresholds.json`만 수정할 수 있다. 장면 관문, 영역 밖 잔차, 차이 면적·개수, 정렬 상관도, 정렬 후 해밍 거리, 동일 이미지 변화량, 최대 국소 변화량을 조정한다. 초기값은 기존 보정값 그대로이며 이번 작업에서 재보정하지 않았다.

판정 규칙의 분기·신뢰 출처·날짜 조건, 평가 하네스, 정답, 안전 테스트, 이 지침은 사람이 관리한다. 루프 중에는 모든 추적 파일 중 thresholds.json 이외를 보호한다. 시작 시 SHA-256을 기록하고 각 단계 전후에 재검사한다. 테스트/평가 프로세스 실행 중에는 보호 파일 쓰기를 감시해 프로세스 그룹을 종료한다. 보호 파일 위반은 점수가 좋아도 즉시 중단하며, 위반 흔적을 자동으로 덮어쓰지 않는다.

초안에서 후보 생성은 외부 JSON 제안 목록을 받는 어댑터로 둔다. 무제한 셸 권한을 가진 에이전트나 LLM을 자동 기동하지 않는다. 루프가 후보 JSON을 검증하고 유일한 수정 허용 파일에 복사한다. 향후 에이전트 연결 시에도 파일 쓰기 권한을 이 파일로 한정한 별도 샌드박스를 사용한다. 해시 검사는 OS 접근 제어를 대신하지 않는다.

## 자료 등록 (사람만)

`tuning/datasets/dev/cases.json`, `tuning/datasets/holdout/cases.json`은 각각 `{ "version": 1, "cases": [...] }`이다. 사례 필드는 `web/eval/tuning/dataset.ts`의 `TuningCase`가 정의한다.

- 사람이 사실 라벨(edited/authentic/miscontextualized/ai_generated), 근거 URL, 이용 허락/라이선스, `humanReviewed: true`를 확인한다. 판단 불가는 정답 라벨이 아닌 시스템의 기권이다.
- `realPhoto`는 실제 사진 기반 사례에만 true. `independentCaseId`는 동일 원본의 크롭·재압축·편집 파생본 전체에 동일하게 붙인다. `splitGroup`은 같은 카메라·장소·사건 묶음의 식별자다. 장면/날짜별 파생본을 따로 세어 30건을 채우지 않는다.
- `input`, `references[].image`는 해당 split 디렉터리 안에 있는 이미지의 상대 `file`과 `sha256`이다. 다른 split 참조와 심볼릭 링크를 통한 경로 탈출은 거부한다. 보관은 최대 512px 썸네일만, 기사 전문·원본 고해상도는 보관하지 않는다.
- `references[].match`, `evidence`, `claimedDate`, `claimText`는 사람이 동결한 후보·근거 스냅샷이다. URL·날짜·해시·200자 이내 요약만 보관한다. 실험마다 원격 검색/기사 fetch/LLM은 하지 않고 같은 픽셀·근거로 생산 판정 함수를 평가한다.
- dev는 서로 독립적인 실제 사진 사례가 최소 30건이어야 한다. AI 그림·동일 원본 파생본은 이를 채우지 못한다. 별도 holdout에도 실제 사진 사례가 있어야 한다. splitGroup·독립 사례 ID·이미지 해시 중 하나라도 겹치면 시작을 거부한다.

사람이 터미널에서 `npm run tuning:holdout -- --seal`을 실행하고 `HOLDOUT`을 직접 입력하면 holdout의 개수·그룹/이미지 해시만 담은 inventory가 생긴다. 정답과 점수는 내보내지 않는다. 루프는 holdout 정답을 파싱하지 않고 이 inventory와 manifest 바이트 해시만 검증한다. inventory와 자료는 시작 전에 커밋한다.

과거 SkyFinder 18장/192쌍 calibration과 18장/192쌍 validation은 이미 결과를 공개한 회귀 자료다. 새로운 비공개 holdout으로 재사용하지 않는다. 기존 같은 장소·다른 시점 반례와 편집 fixture 검사는 그대로 유지한다. 과거 frozen profile 재현 검사도 보호하므로, 기존 보정 결과를 깨뜨리는 후보는 현재 하네스에서 채택되지 않는다.

## 실행 절차 (이번에는 실행하지 않음)

깨끗한 전용 worktree와 `tuning/*` 브랜치를 사람이 만든다. 다른 작업 파일이 있거나 다른 브랜치이면 거부한다. 원래 작업 폴더의 미추적 캡처를 지우지 않는다. Node 24와 기존 의존성·로컬 장면 모델 캐시를 준비한다.

`web/`에서 다음은 준비 상태 확인만 한다:

```sh
npm run tuning:check
```

실행 인자 형식(사람의 별도 실행 지시 후에만 사용):

```sh
npm run tuning:run -- --run --proposals /absolute/path/candidates.json --budget-seconds 600 --max-experiments 5
```

제안 파일은 전체 threshold 객체들의 JSON 배열이다. 에이전트가 dev 결과만 보고 다음 제안을 만든다. 자동으로 실행되는 예약 작업이나 앱 연결은 없다. 실험 예산은 후보 쓰기·커밋·전체 테스트·dev 평가를 합친 시간이며, 한도를 넘으면 프로세스를 종료하고 후보를 거부한다. 기준선 측정에도 같은 예산을 적용한다. 최대 횟수를 넘는 제안은 처리하지 않는다.

각 후보: 허용 파일만 변경 → git commit → 전체 테스트 → dev 평가. 채택 조건은 다음 순서를 고정한다.

1. 전체 테스트 통과. 실패하면 dev 평가도 하지 않는다.
2. dev 오판 정확히 0건. 한 건이라도 있으면 무조건 거부한다.
3. 현재 채택안보다 맞힘 증가. 맞힘이 같으면 판단 불가 감소. 두 값 모두 같으면 거부한다.

표본 수를 줄여 얻은 점수, 누락·실패·불완전한 평가 결과는 거부한다. 정확히 하나의 판정을 내는 고정 평가셋에서는 오판 0·맞힘 동률이면 판단 불가도 같으므로 마지막 동률 조건은 보통 발생하지 않는다. 요청한 순서를 코드에는 그대로 명시했다.

미달 후보는 해당 커밋이 HEAD이며 직전 채택안의 바로 다음 커밋이고 변경 파일이 thresholds.json 하나임을 확인한 뒤 `git reset --hard <직전 채택안>`한다. 다른 작업·보호 파일 변경이 감지되면 자동 reset 대신 중단한다. 기록은 worktree의 Git 관리 디렉터리 `pairsight-tuning/<시각>/`에 남기므로 reset 뒤에도 보존된다.

## holdout과 승격

루프 코드에는 holdout 실행 경로가 없다. 사람이 선택한 최종 커밋에서 `npm run tuning:holdout -- --evaluate`를 직접 실행하고 확인 문구를 입력한다. 자동화/비대화형 stdin에서는 거부한다. 결과를 보고 재튜닝하지 않는다. 문제가 있으면 승격을 보류하고 다음 연구용 새 holdout을 확보한다.

이 루프는 운영 배포를 하지 않는다. 최종 후보를 적용할 때 사람이 버전·캐시·문서를 검토한다. 생산 코드의 분석 캐시 키에는 threshold 내용의 SHA-256을 포함해 다른 기준값의 비교 결과를 재사용하지 않는다.
