# 실제 사례 평가 하네스

판정 규칙(v2, v3)을 실제 사례에 돌려서, 사례마다 결과를 세 가지로 분류합니다.

| 결과 | 뜻 |
| --- | --- |
| **맞힘** | 판정이 정답과 같음 |
| **판단 불가 (놓침)** | 시스템이 판단 불가로 답함. 틀린 건 아니지만 결론을 못 낸 것 |
| **오판** | 정답과 다른 **확정** 판정 전부. 조작 유형만 틀린 경우(예: 편집본을 맥락 조작으로 판정)도 오판 |

정답 라벨은 **사실만** 씁니다: `authentic` · `ai_generated` · `edited` · `miscontextualized`. 판단 불가는 정답이 될 수 없어서, 라벨로 쓰면 오류가 납니다.

보고서는 맨 위에 오판 사례를 근거 카드 전체와 함께 보여주고, 정답 라벨별로 맞힘률·판단 불가율·오판 수를 따로 집계합니다. 같은 근거를 v2(신뢰 출처 규칙 없음)와 v3로 각각 판정하므로, v3가 바꾼 사례도 따로 보입니다.

## 후보 페이지는 어디서 오나 (결제 수단 없이)

사례마다 아래 순서로 정합니다.

| 후보 출처 | 언제 | 측정하는 것 |
| --- | --- | --- |
| **수동 후보** (`sourceUrls`) | 사례에 `sourceUrls`가 있으면 | 검색 없이, 사람이 준 페이지를 실제로 가져와 확인 → 이미지 비교 → 판정. **원본을 스스로 찾는 능력은 측정하지 않음** |
| 신뢰 출처 RSS 색인 | 사례에 `sourceUrls`가 없고 색인이 있으면 (`--index`) | 수집 시작 이후 신뢰 출처 기사에 실린 사진만 찾음 |
| 검색 안 함 | 둘 다 없으면 | 후보가 없으므로 판단 불가가 정상 |

Google Vision 어댑터 코드도 남아 있지만, 이 프로젝트는 지금 쓰지 않습니다. `GOOGLE_VISION_API_KEY`가 설정되어 있을 때만 동작합니다.

**파일럿은 수동 후보로 진행합니다.** 보고서 맨 위에 "검색 없이 수동 후보로 평가함 (n건)"이 표시됩니다. 수동 후보도 그대로 믿지 않습니다. 아래와 같은 경우 후보에서 빠집니다.

- 페이지를 가져오지 못한 경우: robots 금지, 봇 확인 페이지, 유료벽, 오류
- 이미지 비교를 통과하지 못한 경우

## 파일럿 30건: 처음부터 끝까지

### 0. 준비 (한 번만, 키 불필요)

```bash
cd ~/ai-verify/web && cp eval/cases.template.jsonl eval/cases.jsonl && mkdir -p eval/images
```

처음 실행할 때 같은 장면 관문 모델(DINOv2-small, 24 MB)을 Hugging Face에서 `web/.cache/models`로 내려받습니다(약 3초, 키 불필요). 내려받지 못하면 해당 후보 비교는 실패로 기록되고 "원본 확인 미완료"가 됩니다.

템플릿에는 권장 구성대로 30줄이 주석(`//`)으로 들어 있습니다.

| 정답 라벨 | 건수 | id |
| --- | --- | --- |
| 편집 조작 `edited` | 10 | pilot-e01~e10 |
| 맥락 조작 `miscontextualized` | 10 | pilot-c01~c10 |
| 진짜 확인 `authentic` | 5 | pilot-a01~a05 |
| AI 생성 `ai_generated` | 5 | pilot-g01~g05 |

### 1. 사례 하나 넣기

1. **사례를 고르고 정답을 확정합니다.** 정답을 뒷받침하는 공개 근거(원본 기사, 팩트체크 기사, 제작자 공개 등)가 있는 사례만 고릅니다.
2. **퍼진 이미지를 저장합니다.** SNS·커뮤니티에 실제로 돌던 그 이미지를 `eval/images/<id>.jpg`로 저장합니다(예: `eval/images/pilot-e01.jpg`).
   - 편집 조작은 편집된 쪽, 맥락 조작은 잘못된 설명과 함께 돌던 사진, 진짜 확인은 바꾸지 않고 공유된 사진입니다.
   - 원본 기사 이미지가 아니라 **퍼진 쪽**이어야 합니다.
   - 화면 캡처라면 이미지 부분만 잘라 주세요.
   - png/webp/heic도 되며, 그 경우 `image` 확장자를 맞춥니다.
3. **원본 후보 페이지(`sourceUrls`)를 정합니다.** 시스템이 비교할 공개 기사 페이지입니다.

   | 정답 | 넣을 페이지 |
   | --- | --- |
   | 편집 조작 | 편집 **전** 사진이 실린 기사 (가능하면 신뢰 출처 목록의 매체) |
   | 맥락 조작 | 같은 사진이 **더 이른 날짜**에 실린 기사 (게시일이 보이는 페이지) |
   | 진짜 확인 | 그 사진이 실린 보도 원문 |
   | AI 생성 | 보통 없음. 넣지 않아도 됨 (`[]`) |

   - 기사에 사진이 여러 장이면 `{"url":"기사 URL","imageUrl":"비교할 사진 URL"}`로 사진을 지정합니다. 지정하지 않으면 대표 이미지(og:image)와 본문 첫 사진, 최대 2장을 비교합니다.
   - 1~5개까지 넣을 수 있습니다. 로그인·유료 페이지는 확인할 수 없습니다.
4. **`eval/cases.jsonl`의 해당 줄을 채우고 앞의 `//`를 지웁니다.**

   ```json
   {"id":"pilot-c01","image":"images/pilot-c01.jpg","claim":"어제 광화문 집회 현장","claimedDate":"2026-10-12","label":"miscontextualized","sourceUrls":["https://www.yna.co.kr/view/AKR2019..."],"source":"2019-08-15 연합뉴스 원본, 팩트체크 URL"}
   ```

   | 필드 | 쓰는 법 |
   | --- | --- |
   | `id` | 템플릿의 id를 그대로 (파일 이름과 같게) |
   | `image` | `images/<id>.jpg` |
   | `label` | 사실 4종 중 하나 |
   | `claim` | 게시물이 주장한 내용, 200자 이내. 없으면 `""` |
   | `claimedDate` | 게시물이 주장한 촬영 날짜 `YYYY-MM-DD`. **맥락 조작은 꼭** 넣기(없으면 v3 맥락 규칙이 동작할 수 없음). 없으면 `null` |
   | `sourceUrls` | 위 3번의 후보 페이지 |
   | `source` | 정답 근거 URL과 짧은 메모. 오판을 다시 볼 때 보고서에 그대로 나옴 |

5. **검사합니다.** 네트워크 요청 없이 형식, 이미지 유무, 라벨별 건수, 맥락 조작 날짜 누락, 정답 근거 누락, 수동 후보 수를 확인합니다.

   ```bash
   cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --validate
   ```

6. **그 사례 하나만 돌려 봅니다.** 실제로 그 페이지를 가져옵니다.

   ```bash
   cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --only pilot-c01
   ```

   보고서의 사례별 요약에서 후보(확인/일치/신뢰)가 0/0/0이면, 페이지 확인 단계에서 걸린 것입니다. 경고 열을 보세요. robots 금지, 봇 확인, 응답 오류 중 하나입니다.

### 2. 30건 전체 실행

```bash
cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --out eval/out/pilot-1
```

- 색인도 함께 쓰려면 `--index`를 붙입니다(경로 생략 시 `web/.data/rss-index.jsonl`). 색인 파일이 없으면 경고만 하고 계속합니다. `sourceUrls`가 있는 사례는 여전히 수동 후보를 씁니다.

  ```bash
  cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --index --out eval/out/pilot-1-index
  ```

- 결과는 `eval/out/pilot-1/report.md`(보고서)와 `results.json`(사례별 상세, 혼동 행렬)에 남습니다.
- 사례는 하나씩 처리하고, 같은 사이트는 1초 간격으로 가져옵니다(robots의 Crawl-delay가 더 길면 그 값을 따릅니다).

## 실제 모드에서 하는 일, 하지 않는 일

| 단계 | 실제 모드 |
| --- | --- |
| 후보 | 수동 후보 또는 RSS 색인. 웹 검색 없음 |
| 후보 페이지 확인 | 앱과 같은 정책: robots 준수, 사이트별 1초 간격, 리다이렉트·내부망 차단. 봇 확인·유료벽은 "확인 못 함". 우회하지 않음 |
| 날짜 | 후보 페이지의 게시일 메타데이터만. Wayback은 연결하지 않음 |
| 이미지 비교 | 실제 pHash·정렬·차이 영역 |
| 출처 기록 | EXIF 유무만. **C2PA·워터마크 검증 없음** |
| 팩트체크·맥락 LLM | 연결하지 않음 |

**결과를 읽을 때 알아야 할 것:**

- **진짜 확인 판정은 실제 모드에서 나올 수 없습니다.** 진짜 확인에는 서명된 촬영 기록(C2PA)이 필요한데 하네스는 C2PA를 검증하지 않습니다. 진짜 사례 5건은 판단 불가가 정상이고, 이 5건의 역할은 **진짜 사진을 조작으로 판정하는 오판이 없는지** 확인하는 것입니다.
- **AI 생성도 대부분 판단 불가가 됩니다.** C2PA나 검증된 워터마크가 필요하기 때문입니다. AI 생성 사례 역시 오판이 없는지 보는 용도입니다.
- 맞힘을 기대할 수 있는 것은 v3 신뢰 출처 규칙이 다루는 **편집 조작과 맥락 조작**이고, 그것도 후보 페이지가 **신뢰 출처 목록**에 있을 때입니다. 목록 밖 페이지는 v2 규칙이라 판단 불가가 많습니다.
- **합성 fixture의 한계:** 합성 fixture는 모두 같은 장면 틀로 그려져서 "완전히 다른 사진을 걸러내는 능력"을 시험하지 못합니다. 엉뚱한 후보 페이지를 넣은 사례를 파일럿에 몇 개 섞어 두면, 이 부분을 확인할 수 있습니다.
- 결과 파일에는 이미지·썸네일·페이지 본문이 들어가지 않고, URL·날짜·비교 수치·근거 요약만 들어갑니다. `eval/images/`와 `eval/out/`은 커밋되지 않습니다.

## 보고서 읽는 법

1. **오판 (맨 위):** 사례마다 판정 이유, 적용 규칙·강도, 핵심 발견, 정답 출처, 후보 출처, 근거 카드 전체, 후보 비교 수치(신뢰 출처, 날짜와 그 출처, 정렬 상관도, pHash, 변화 비율, 차이 영역)를 보여줍니다.
2. **정답 라벨별 집계:** v3와 v2 각각의 맞힘률·판단 불가율·오판 수. 비율의 분모는 실행된 사례이고, 실행 실패는 따로 셉니다.
3. **v2 → v3에서 바뀐 사례:** 바뀐 판정이 맞힘인지 오판인지 보여줍니다.
4. **사례별 요약:** 후보 출처, 후보 수(확인/이미지 일치/신뢰 출처), 핵심 발견, 부족한 근거, 경고.

**30건으로 말할 수 있는 것:** 오판이 0건이어도 "실제 오판률은 대략 10% 이하"(≈ 3/30)까지만 말할 수 있습니다. 파일럿의 목적은 **실패 유형을 찾는 것**이고, 정확도 수치를 내는 것이 아닙니다.

## 키 없이 하네스만 확인

저장소의 합성 fixture로 돌립니다.

```bash
cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH PAIRSIGHT_MOCK_DELAY_MS=0 npm run -s eval -- --cases eval/cases.example.jsonl --mock --out eval/out/smoke
```

**옵션:**

- `--validate`: 검사만 하고 실행하지 않음
- `--only <id>`: 사례 하나만 실행
- `--limit N`: 앞에서부터 N건만 실행
- `--out <폴더>`: 결과를 쓸 위치
- `--mock`: 합성 fixture 전용 모의 모드
