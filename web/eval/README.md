# 실제 사례 평가 하네스

판정 규칙(v2, v3)을 실제 사례에 돌려서 다음을 측정합니다.

- 판정별 분포와 판단 불가 비율
- 오판 목록: 정답과 반대 판정, 조작 유형 혼동, 근거 없는 확정
- 사례별 근거 요약

같은 근거를 v2(신뢰 출처 목록 없음)와 v3(운영 목록)로 각각 판정하므로, v3가 바꾼 사례가 따로 보입니다.

## 실행

`web/` 폴더에서 실행합니다.

```bash
cd ~/ai-verify/web
```

1. **하네스가 도는지 확인 (키 불필요).** 저장소에 있는 합성 fixture로 돌립니다.

   ```bash
   PATH=$HOME/.local/node/bin:$PATH PAIRSIGHT_MOCK_DELAY_MS=0 npm run eval -- --cases eval/cases.example.jsonl --mock --out eval/out/smoke
   ```

2. **실제 사례 평가.**

   ```bash
   PATH=$HOME/.local/node/bin:$PATH GOOGLE_VISION_API_KEY=발급받은키 npm run eval -- --cases eval/cases.jsonl
   ```

   - 결과는 `eval/out/<시각>/report.md`(사람이 읽는 보고서)와 `results.json`(사례별 상세, 혼동 행렬)에 남습니다.
   - 옵션:
     - `--out <폴더>`: 결과를 쓸 위치
     - `--limit 10`: 앞에서부터 N건만 실행
     - `--only <id>`: 사례 하나만 실행
     - `--mock`: 키가 있어도 모의 모드로 실행

**키가 없으면 자동으로 mock 모드로 돌아갑니다.** 이때 실제 사진은 모두 "원본 없음 → 판단 불가"가 됩니다. 보고서 맨 위에 경고가 붙고, 결과는 정확도와 무관합니다.

## 실제 모드에서 하는 일, 하지 않는 일

| 단계 | 실제 모드 |
| --- | --- |
| 후보 찾기 | Google Vision Web Detection (`lib/providers/google-vision.ts`). 이미지를 메타데이터 없는 1600px 이하 JPEG로 바꿔 보내고, 키는 요청 헤더로만 보냄 |
| 후보 페이지 확인 | 앱과 같은 `PolicyFetch`: robots 준수, 출처별 1초 간격, 리다이렉트·내부망 차단, 봇 확인/유료벽은 확인 못 함으로 처리 |
| 날짜 | 후보 페이지의 게시일 메타데이터만. **Vision은 날짜를 주지 않고**, Wayback 조회는 연결하지 않음 |
| 이미지 비교 | 실제 pHash·정렬·차이 영역 |
| 출처 기록 | EXIF 유무만. C2PA·워터마크 검증은 없음 |
| 팩트체크·맥락 LLM | 연결하지 않음 |

v3가 해결하려는 "메타데이터가 지워진 SNS 이미지"에 가까운 조건입니다. 반대로 팩트체크·C2PA로 판정되는 사례는 이 하네스에서 판단 불가가 될 수 있습니다. 보고서의 "보류"에 그렇게 나타납니다.

**외부 전송 주의:** 실제 모드에서는 평가 이미지가 Google로 전송됩니다. 전송해도 되는 이미지만 넣어 주세요. 이미지와 결과 폴더(`eval/images/`, `eval/out/`)는 `.gitignore`에 있어 커밋되지 않습니다. 결과 파일에는 이미지·썸네일·페이지 본문이 들어가지 않고, URL·날짜·비교 수치만 들어갑니다.

## 준비할 것

### 1. Google Cloud Vision API 키

1. Google Cloud 프로젝트에서 **Cloud Vision API**를 사용 설정합니다.
2. API 키를 만들고, 키 제한에서 **Cloud Vision API만** 허용하도록 설정합니다.
3. 셸 환경 변수 `GOOGLE_VISION_API_KEY`에 넣습니다. 파일이나 저장소에 적지 마세요.
4. 가격: Web Detection은 월 1,000건까지 무료, 이후 1,000건당 $3.50입니다(2026-10-18 확인, [reverse-search-comparison.md](../../replica/reverse-search-comparison.md)). 사례 100건 평가는 무료 구간 안에 들어갑니다.

### 2. 사례 수

목표는 **최소 100건**이고, 아래 구성을 권합니다.

| 정답 라벨 | 권장 건수 | 어떤 사례 |
| --- | --- | --- |
| `edited` 편집 조작 | 25 | 통신사·언론 원본 사진을 일부 바꿔 퍼뜨린 사례 |
| `miscontextualized` 맥락 조작 | 30 | 옛 보도사진을 새 사건 사진처럼 퍼뜨린 사례. **주장한 날짜(`claimedDate`)를 꼭 적기** |
| `authentic` 진짜 확인 | 20 | 언론 보도사진을 그대로(재압축·잘라내기만) 공유한 사례 |
| `ai_generated` AI 생성 | 10 | 생성 이미지임이 확인된 사례 |
| `inconclusive` 판단 불가 | 15 | 사람이 조사해도 결론이 안 나는 사례. 근거 없는 확정을 잡아내는 용도 |

- 한국 언론·커뮤니티 유통 사례를 절반 이상 넣어 주세요. 한국어 커버리지는 아직 측정한 적이 없습니다.
- **반대 판정 0건이 목표**입니다. 100건에서 0건이 나와도 실제 오판률이 3%(≈ 3/n)보다 낮다고만 말할 수 있습니다. 1%까지 말하려면 300건이 필요합니다.
- 유형별 20건이면 정확도 추정의 오차 폭이 ±20%p 안팎으로 큽니다. 임계값을 조정하려면 유형별 50건 이상을 권합니다.

### 3. 라벨 형식 (`eval/cases.jsonl`)

한 줄에 사례 하나씩 적습니다(JSON Lines). `//`로 시작하는 줄은 무시합니다. 예시는 `cases.example.jsonl`에 있습니다.

```json
{"id":"kr-0001","image":"images/kr-0001.jpg","claim":"어제 광화문 집회 현장 사진","claimedDate":"2026-10-12","label":"miscontextualized","source":"2019-08-15 원본 기사 URL / 팩트체크 기사 URL"}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `id` | 예 | 고유한 사례 이름 |
| `image` | 예 | 이미지 경로. 이 파일 기준 상대 경로(`images/…`). JPG/PNG/WebP/HEIC |
| `label` | 예 | `authentic` · `ai_generated` · `edited` · `miscontextualized` · `inconclusive` 중 하나 |
| `claim` | 아니요 | 게시물이 주장하는 내용, 200자 이내. 앱에서 사용자가 쓰는 "유포 주장"과 같음 |
| `claimedDate` | 아니요 | 게시물이 주장하는 촬영 날짜 `YYYY-MM-DD`. 맥락 조작 사례에서는 사실상 필수 |
| `source` | 권장 | 정답의 근거: 원본 기사, 팩트체크 기사 URL, 메모 |

**라벨 기준(용어집과 같음):**

- **`authentic`:** 사진이 바뀌지 않았고, 주장(있다면)이 사진의 실제 맥락과 맞음
- **`edited`:** 원래 사진의 일부가 바뀌었거나 합성됨
- **`miscontextualized`:** 사진은 그대로인데, 다른 시점·장소·사건의 사진으로 쓰임
- **`ai_generated`:** 이미지 전체가 생성됨
- **`inconclusive`:** 사람이 확인해도 정답을 정할 근거가 없음. "모르겠다"를 정답으로 둔 사례

정답을 정한 근거(`source`)가 없는 사례는 넣지 않는 것이 좋습니다. 보고서의 오판 목록에 `source`가 그대로 표시되므로, 오판을 다시 확인할 때 씁니다.

## 출력 읽는 법

- **반대 판정:** 진짜를 조작으로, 또는 조작을 진짜로 판정한 경우. 가장 먼저 봐야 할 목록입니다.
- **근거 없는 확정:** 정답이 판단 불가인데 확정 판정을 낸 경우. v3 규칙이 너무 느슨하면 여기에 나타납니다.
- **보류:** 정답은 확정인데 판단 불가로 답한 경우. 틀린 것은 아니지만, 이 비율이 v3로 줄어드는지가 이번 개선의 목표입니다.
- **후보(확인/일치/신뢰):** 확인한 후보 페이지 수 / 이미지 비교를 통과한 수 / 그중 신뢰 출처 수. 신뢰 출처가 0이면 v3는 동작할 수 없습니다. 이 경우에는 목록이나 검색 커버리지 문제입니다.
