# 실제 사례 평가 하네스

판정 규칙(v2, v3)을 실제 사례에 돌려서, 사례마다 결과를 세 가지로 분류합니다.

| 결과 | 뜻 |
| --- | --- |
| **맞힘** | 판정이 정답과 같음 |
| **판단 불가 (놓침)** | 시스템이 판단 불가로 답함. 틀린 건 아니지만 결론을 못 낸 것 |
| **오판** | 정답과 다른 **확정** 판정 전부. 조작 유형만 틀린 경우(예: 편집본을 맥락 조작으로 판정)도 오판 |

정답 라벨은 **사실만** 씁니다: `authentic` · `ai_generated` · `edited` · `miscontextualized`. 판단 불가는 정답이 될 수 없으므로 라벨로 쓰면 오류가 납니다.

보고서는 오판 사례를 **맨 위에** 근거 카드 전체와 함께 보여주고, 정답 라벨별로 맞힘률·판단 불가율·오판 수를 따로 집계합니다. 같은 근거를 v2(신뢰 출처 규칙 없음)와 v3로 각각 판정하므로, v3가 바꾼 사례도 따로 보입니다.

## 파일럿 30건: 처음부터 끝까지

### 0. 준비 (한 번만)

1. **Google Cloud Vision API 키**
   - Google Cloud 프로젝트에서 Cloud Vision API를 사용 설정하고 API 키를 만듭니다.
   - 키 제한에서 **Cloud Vision API만** 허용합니다.
   - 키는 셸 환경 변수 `GOOGLE_VISION_API_KEY`로만 넣고, 파일이나 저장소에 적지 마세요.
   - 월 1,000건까지 무료입니다(2026-10-18 확인). 30건 파일럿은 무료 범위입니다.
2. **템플릿 복사**

   ```bash
   cd ~/ai-verify/web && cp eval/cases.template.jsonl eval/cases.jsonl && mkdir -p eval/images
   ```

   템플릿에는 권장 구성대로 30줄이 주석(`//`)으로 들어 있습니다.

   | 정답 라벨 | 건수 | id |
   | --- | --- | --- |
   | 편집 조작 `edited` | 10 | pilot-e01~e10 |
   | 맥락 조작 `miscontextualized` | 10 | pilot-c01~c10 |
   | 진짜 확인 `authentic` | 5 | pilot-a01~a05 |
   | AI 생성 `ai_generated` | 5 | pilot-g01~g05 |

### 1. 사례 하나 넣기

1. **사례를 고르고 정답을 확정합니다.** 정답을 뒷받침하는 공개 근거(원본 기사, 팩트체크 기사, 제작자 공개 등)가 있는 사례만 고릅니다. 근거가 없으면 넣지 않습니다.
2. **퍼진 이미지를 저장합니다.** SNS·커뮤니티에 실제로 돌던 그 이미지를 `eval/images/<id>.jpg`로 저장합니다. 예: `eval/images/pilot-e01.jpg`
   - 편집 조작은 편집된 쪽, 맥락 조작은 잘못된 설명과 함께 돌던 사진, 진짜 확인은 바꾸지 않고 공유된 사진입니다.
   - 원본 기사 이미지가 아니라 **퍼진 쪽**이어야 합니다. 원본은 시스템이 찾아내야 하는 대상입니다.
   - 화면 캡처보다 이미지 파일 자체가 좋습니다. 캡처라면 이미지 부분만 잘라 주세요.
   - png/webp/heic도 됩니다. 그 경우 `image` 값의 확장자를 맞춰 주세요.
3. **`eval/cases.jsonl`의 해당 줄을 채우고 앞의 `//`를 지웁니다.**

   ```json
   {"id":"pilot-c01","image":"images/pilot-c01.jpg","claim":"어제 광화문 집회 현장","claimedDate":"2026-10-12","label":"miscontextualized","source":"2019-08-15 원본 기사 URL, 팩트체크 URL"}
   ```

   | 필드 | 쓰는 법 |
   | --- | --- |
   | `id` | 템플릿의 id를 그대로 씀 (파일 이름과 같게) |
   | `image` | `images/<id>.jpg` |
   | `label` | 사실 4종 중 하나 |
   | `claim` | 게시물이 주장한 내용, 200자 이내. 없으면 `""` |
   | `claimedDate` | 게시물이 주장한 촬영 날짜 `YYYY-MM-DD`. **맥락 조작은 꼭** 넣기(없으면 v3 맥락 규칙이 동작할 수 없음). 없으면 `null` |
   | `source` | 정답 근거 URL과 짧은 메모. 오판을 다시 확인할 때 보고서에 그대로 나옴 |

4. **형식과 파일을 검사합니다.** 네트워크 요청 없이 형식, 이미지 유무, 라벨별 건수, 맥락 조작 날짜 누락, 정답 근거 누락을 확인합니다.

   ```bash
   cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --validate
   ```

5. **그 사례 하나만 돌려 봅니다.**

   ```bash
   cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --only pilot-c01
   ```

### 2. 30건 전체 실행

```bash
cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH npm run -s eval -- --cases eval/cases.jsonl --out eval/out/pilot-1
```

- 결과는 `eval/out/pilot-1/report.md`(보고서)와 `results.json`(사례별 상세, 혼동 행렬)에 남습니다.
- 키가 환경 변수에 없으면 **mock 모드**로 돌고, 보고서 맨 위에 경고가 붙습니다. mock 모드에서는 실제 사진이 모두 판단 불가가 되므로 결과가 의미 없습니다.
- 사례는 하나씩 순서대로 처리합니다. 후보 페이지는 사이트마다 1초 간격으로 가져와서, 30건에 몇 분 걸릴 수 있습니다.

## 실제 모드에서 하는 일, 하지 않는 일

| 단계 | 실제 모드 |
| --- | --- |
| 후보 찾기 | Google Vision Web Detection. 이미지를 메타데이터 없는 1600px 이하 JPEG로 바꿔 보내고, 키는 요청 헤더로만 보냄 |
| 후보 페이지 확인 | 앱과 같은 정책: robots 준수, 사이트별 1초 간격, 리다이렉트·내부망 차단. 봇 확인 페이지·유료벽은 "확인 못 함" |
| 날짜 | 후보 페이지의 게시일 메타데이터만. Vision은 날짜를 주지 않고, Wayback은 연결하지 않음 |
| 이미지 비교 | 실제 pHash·정렬·차이 영역 |
| 출처 기록 | EXIF 유무만. **C2PA·워터마크 검증 없음** |
| 팩트체크·맥락 LLM | 연결하지 않음 |

**파일럿 결과를 읽을 때 알아야 할 것:**

- **진짜 확인 판정은 실제 모드에서 나올 수 없습니다.** 진짜 확인 규칙은 서명된 촬영 기록(C2PA)이 필요한데 여기서는 검증하지 않습니다. 진짜 사례 5건은 판단 불가가 정상입니다. 이 5건의 역할은 **진짜 사진을 조작으로 판정하는 오판이 없는지** 확인하는 것입니다.
- **AI 생성도 대부분 판단 불가가 됩니다.** AI 생성 규칙은 C2PA나 검증된 워터마크가 필요하기 때문입니다. AI 생성 사례 역시 오판(예: 편집 조작으로 판정)이 없는지 보는 용도입니다.
- 이번 파일럿에서 맞힘을 기대할 수 있는 것은 v3 신뢰 출처 규칙이 다루는 **편집 조작과 맥락 조작**입니다.
- **외부 전송:** 실제 모드에서는 평가 이미지가 Google로 전송됩니다. 전송해도 되는 이미지만 넣어 주세요. `eval/images/`와 `eval/out/`은 커밋되지 않습니다. 결과 파일에는 이미지·썸네일·페이지 본문이 들어가지 않고, URL·날짜·비교 수치·근거 요약만 들어갑니다.

## 보고서 읽는 법

1. **오판 (맨 위)**
   - 사례마다 판정 이유, 적용 규칙·강도, 핵심 발견, 정답 출처, 근거 카드 전체, 후보 비교 수치를 보여줍니다.
   - 후보 비교 수치는 신뢰 출처, 날짜와 그 출처, 정렬 상관도, pHash, 변화 비율, 차이 영역입니다.
   - 오판 하나하나가 규칙 수정 후보입니다.
2. **정답 라벨별 집계:** v3와 v2 각각의 맞힘률·판단 불가율·오판 수입니다. 비율의 분모는 실행된 사례이고, 실행 실패는 따로 셉니다.
3. **v2 → v3에서 바뀐 사례:** v3 규칙이 결과를 바꾼 사례와, 그 변화가 맞힘인지 오판인지 보여줍니다.
4. **사례별 요약:** 후보 수(확인/이미지 일치/신뢰 출처), 핵심 발견, 부족한 근거, 경고입니다. 신뢰 출처가 0이면 v3는 동작할 수 없습니다. 이 경우에는 목록이나 검색 커버리지 문제입니다.

**30건으로 말할 수 있는 것:** 오판이 0건이어도 "실제 오판률은 대략 10% 이하"(≈ 3/30)까지만 말할 수 있습니다. 유형별 5~10건은 비율을 추정하기에 너무 적습니다. 파일럿의 목적은 **실패 유형을 찾는 것**이고, 정확도 수치를 내는 것이 아닙니다. 수치를 말하려면 유형별 50건 이상이 필요합니다.

## 키 없이 하네스만 확인

저장소에 있는 합성 fixture로 돌립니다.

```bash
cd ~/ai-verify/web && PATH=$HOME/.local/node/bin:$PATH PAIRSIGHT_MOCK_DELAY_MS=0 npm run -s eval -- --cases eval/cases.example.jsonl --mock --out eval/out/smoke
```

**옵션:**

- `--validate`: 검사만 하고 실행하지 않음
- `--only <id>`: 사례 하나만 실행
- `--limit N`: 앞에서부터 N건만 실행
- `--out <폴더>`: 결과를 쓸 위치
- `--mock`: 키가 있어도 모의 모드로 실행
