# 신뢰 출처 목록 (판정 규칙 v3)

작성일: 2026-10-19 · 목록 파일: [`web/config/trusted-sources.json`](../web/config/trusted-sources.json) · 코드: `web/lib/verification/trusted-sources.ts`

## 이 목록이 하는 일, 하지 않는 일

- **하는 일:** 실제로 가져와 확인한 페이지가 이 목록의 도메인일 때만, 그 페이지에서 찾은 **이미지 비교 결과**와 **페이지 게시일**을 근거 강도 '중~강'으로 쳐 줍니다. 그래서 C2PA·워터마크·팩트체크가 없는 SNS 유통 이미지도 '편집 조작'이나 '맥락 조작' 판정까지 갈 수 있습니다.
- **하지 않는 일:** 목록에 있는 매체의 기사 내용이 사실이라고 보증하지 않습니다. 신뢰 출처도 잘못된 사진을 쓰거나, 독자 제보 사진을 싣거나, 나중에 사진을 바꿀 수 있습니다. 화면 문구는 항상 "신뢰 출처 원본과 다름"처럼 **관찰**만 말하고, 편집 의도를 단정하지 않습니다.
- 목록에 없는 출처는 v2 규칙을 그대로 따릅니다. 즉 이미지 비교와 페이지 게시일만으로는 판정하지 않습니다.

## 선정 기준

아래를 **모두** 만족하는 출처만 넣습니다.

1. **편집 책임이 있는 조직입니다.** 정정·반론 보도 절차가 있고, 사진 출처(촬영자·제공처) 표기 관행이 있습니다.
2. **사진의 1차 생산자이거나 1차 유통 경로입니다.** 통신사, 자체 사진기자를 둔 전국 단위 매체, 정부·공공기관의 공식 발표 채널이 여기에 해당합니다.
3. **도메인을 그 조직이 직접 운영합니다.** 포털 재전송 페이지, 블로그, 커뮤니티, 사용자 업로드 영역은 넣지 않습니다.
4. **게시일 메타데이터를 페이지에 남깁니다.** `article:published_time`이나 `datePublished`가 있어야 맥락 조작 규칙에 쓸 수 있습니다.

### 현재 초안의 분류

| 분류 (`category`) | 포함 | 비고 |
| --- | --- | --- |
| `kr_wire` 국내 통신사 | 연합뉴스, 뉴시스, 뉴스1 | |
| `kr_broadcast` 지상파·보도전문채널 | KBS, MBC, SBS, YTN | |
| `kr_press` 전국 종합일간지 | 조선, 중앙, 동아, 한겨레, 경향, 한국일보 | 발행 부수나 성향 기준이 아니라 "자체 사진기자를 둔 전국 종합지"라는 범주로 골랐습니다. 다른 전국지 추가는 편집 검토로 정합니다. |
| `intl_wire` 국제 통신사 | AP, Reuters, AFP | |
| `government` 정부·공공기관 | `go.kr` 전체, `korea.kr`(정책브리핑) | `go.kr`은 정부 기관만 등록할 수 있는 도메인이라 하위 도메인 전체를 포함합니다. `or.kr`처럼 누구나 등록할 수 있는 도메인은 넣지 않습니다. |

**이 목록은 초안입니다.** 도메인은 2026-10-19에 작성했고, 각 도메인을 그 조직이 실제로 소유하는지는 아직 확인하지 않았습니다. 출시 전에 편집 담당자가 검토하고, 파일의 `reviewedBy`에 검토자와 날짜를 적어 주세요.

### 넣지 않는 것

- 포털 뉴스(재전송), 블로그·카페·커뮤니티, SNS 계정 페이지
- 팩트체크 기관 사이트: 팩트체크는 별도의 `fact_check` 규칙(v2)으로 다룹니다. 단, 통신사 도메인 아래의 팩트체크 페이지는 통신사 항목으로 매칭됩니다.
- 이미지 저장소·스톡 사이트: 게시일이 촬영 시점을 뜻하지 않습니다.

## 목록 바꾸는 법 (코드 수정 없음)

1. `web/config/trusted-sources.json`의 `sources`에 항목을 추가하거나 뺍니다. 필드는 `id`(고유), `name`(화면 표시명), `domains`(배열), `category`(위 5개 중 하나), `basis`(선정 근거 한 줄)입니다.
2. `version`을 올리고 `reviewedBy`에 검토자와 날짜를 적습니다.
3. 서버는 파일 수정 시각이 바뀌면 다음 판정 때 목록을 다시 읽습니다. 재빌드나 재시작이 필요 없습니다.
4. 파일 형식이 잘못되면 **빈 목록으로 동작**합니다(v2 규칙만 적용, 서버 로그에 오류 기록). 판정이 더 보수적인 쪽으로 기울도록 한 설계입니다.
5. 운영 환경에서 다른 경로를 쓰려면 `PAIRSIGHT_TRUSTED_SOURCES=/path/to/list.json`을 설정합니다.

mock 모드(`PAIRSIGHT_PROVIDERS=mock`)에서는 `trusted-sources.mock.json`의 가상 도메인(`wire.example.test` 등)이 함께 합쳐집니다. 실제 언론사 이름으로 가짜 기사를 만들지 않으려고 fixture에는 가상 도메인만 씁니다.

## 매칭 규칙과 위장 대응

- **판정 대상은 리다이렉트를 따라간 최종 페이지 주소입니다.** 검색 결과에 적힌 주소가 아닙니다. 그 페이지를 실제로 가져와 이미지 비교를 통과한 경우에만 신뢰 출처 규칙을 적용합니다.
- 도메인은 정확히 같거나, 점 경계를 둔 하위 도메인일 때만 매칭합니다. `yna.co.kr.evil.com`이나 `fakeyna.co.kr`은 매칭되지 않습니다(테스트 포함).
- 국제화 도메인은 URL 파서가 punycode로 바꾼 값으로 비교하므로, 비슷하게 생긴 유니코드 문자로는 매칭되지 않습니다.
- **남은 위험:**
  - 신뢰 출처 도메인 안에 독자 제보·사용자 업로드 영역이 있으면 그 페이지도 매칭됩니다.
  - 매체가 사진을 나중에 교체하거나 게시일 메타데이터를 고칠 수 있습니다. `dateDisputed`가 이 경우 일부를 잡아냅니다.
  - 매체가 다른 곳의 조작 이미지를 그대로 실을 수 있습니다. 이 경우 "신뢰 출처와 다름"이 거꾸로 나올 수 있어서, 편집 조작 규칙은 신뢰 출처 쪽이 **더 이르게** 게시됐을 때만 적용합니다.
