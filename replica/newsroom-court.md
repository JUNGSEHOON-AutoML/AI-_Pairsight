**이번 범위:** 이 문서, 법정 레이어 최소 구현(`web/lib/court/`, `web/lib/llm/`), mock LLM 테스트(`web/tests/court.test.ts`).

## 1. 한 줄 요약

**판정은 코드가 하고, 에이전트는 근거 카드를 인용한 주장만 합니다.** 공방의 결과로 판정이 바뀌는 경우는 하나뿐입니다. 근거 있는 합리적 의심이 있으면 **판단 불가로 내려가는 것**입니다. 판정을 올리거나 다른 판정으로 바꾸는 길은 코드에 없습니다.

```
업로드 ─▶ [기존 파이프라인] 후보 찾기 → 페이지 확인 → 이미지 비교·같은 장면 관문 → 출처 기록
              │
              ▼
        근거 카드 E1…, S1…  ──▶  판사 = 규칙 v3 (decideVerdict, 코드)
                                   │
                    판단 불가? ─────┤──▶ 예: 공방 없음, LLM 호출 0
                                   ▼ 아니오
                     검사 ─ 변호인 ─ 배심원 ×3 ─ 서기   (LLM, 도구 없음)
                                   │   모든 답은 코드가 검증 (court.ts)
                                   ▼
                 최종 판정 = 판사 판정 또는 판단 불가  +  판결문
```

## 2. 법정 레이어

### 2-1. 역할

| 역할 | 누가 | 입력 | 출력 | 권한 |
| --- | --- | --- | --- | --- |
| 증거 | 코드 (`buildDocket`) | 기존 근거 카드(Evidence), 검증된 후보 페이지(SourceMatch) | 사건 기록: 카드 ID, 종류, 결과, 강도, 측정값, 페이지 발췌(신뢰 안 함) | 새 사실 추가 불가. 카드만 증거 |
| 판사 | 코드 (`decideVerdict`, 규칙 v3) | 근거 카드, 주장 날짜, 신뢰 출처 목록 | 판정, 규칙, 이유, 부족한 근거 | 판정을 정하는 유일한 주체 |
| 검사 | 에이전트 (LLM) | 사건 기록 | "가짜" 쪽 논리, 각 주장에 카드 인용 (최대 4) | 판정 권한 없음 |
| 변호인 | 에이전트 (LLM) | 사건 기록 | 대안 설명(같은 장소 다른 시점, 잘라내기·재압축, 날짜 오류, 다른 사건 등)과 카드 인용 (최대 4) | 판정 권한 없음 |
| 배심원 ×3 | 에이전트 (LLM), 관점이 서로 다름 | 사건 기록, 검증을 통과한 검사·변호인 주장 | 유지, 또는 판단 불가 + 인용된 의심 1개 | **판단 불가로 내리기만** 가능 |
| 서기 | 에이전트 (LLM) + 코드 | 판정, 검증된 주장과 의심 | 판결문 요약(인용 필수) | 판정 문장, 직접 확인하는 법은 코드가 씀 |

**배심원 관점(`JUROR_PERSPECTIVES`)**
- 사진 기술: 정렬, 차이 영역, 잘라내기, 압축
- 날짜·맥락: 게시일, 날짜 출처, 날짜 다툼
- 출처 신뢰: 어떤 페이지인지, C2PA, 팩트체크

### 2-2. 코드가 강제하는 규칙 (`web/lib/court/court.ts`)

| 원칙 | 구현 | 테스트 |
| --- | --- | --- |
| 기존 근거 카드만 증거 | `buildDocket`은 기존 Evidence와 `verified=true`인 SourceMatch만 받는다. ID는 E1…, S1… | 미검증 후보 인용 거부 |
| 모델 자유 문장은 증거가 아님 | 실제 카드 ID라도 모델이 쓴 새 인물·날짜·행위가 증명되는 것은 아니다. 화면/이벤트의 발언은 코드가 인용 카드의 요약·기록 날짜로 재구성하며 모델 문장은 버린다. 서기는 검증된 공방 주장/의심만 선택한다 | 기존 ID + 조작된 사실, 서기의 새 의심 반례 |
| 인용 없는 주장은 폐기 | `checkStatement`: 내용이 없거나, `cite`가 비었거나, 없는 카드 ID를 하나라도 인용하면 폐기하고 이유를 `rejected`에 남긴다. 주장(P1, D1)은 증거가 아니라서 인용 대상이 될 수 없다 | 근거 없는 주장 폐기 |
| 판사 = 코드 | 최종 판정은 `judgeVerdict` 또는 `inconclusive` 둘 중 하나뿐이다 | 전체 |
| 변호인은 판정에 반대하는 쪽만 | 변호인 대안의 종류는 그 판정을 내릴 수 있는 의심(`DOUBTS_FOR`)이나 `other`여야 한다 | 조작 쪽 논리를 대안으로 내면 폐기 |
| 배심원은 올릴 수 없음 | `decision`이 `uphold`/`inconclusive` 말고 다른 값이면 거부하고 유지로 처리한다 | 배심원 판정 올리기 거부 |
| 합리적 의심만 판단 불가 | 의심 종류가 그 판정에 해당하고(`DOUBTS_FOR`), 인용 카드 중 하나의 **측정값**에 그 의심의 신호가 있어야 한다(`DOUBT_SIGNAL`). 카드 종류만 맞는 것으로는 부족하다. 아래 표 참조 | 신호가 있는 같은 장소 다른 시점 → 판단 불가. 신호 없는 카드, 관계없는 카드는 거부 |
| 판단 불가면 공방 없음 | 판사가 `inconclusive`이면 LLM을 한 번도 부르지 않는다 | 호출 0 |
| 페이지 텍스트는 데이터 | 아래 2-4 | 프롬프트 주입 |
| 도구 권한 없음 | `LLMRequest`에는 `system`, `prompt`, `schema`만 있다. 함수 호출, 검색, URL 열기 필드가 타입에 없다 | 요청 키 검사 |

**하나의 의심으로 충분한가?** 그렇습니다. 형사 재판의 "합리적 의심이 없을 정도의 증명"과 같은 방향입니다. 판단 불가로 내리는 쪽은 안전한 실패이고, 잘못된 편집 조작 판정이 가장 위험한 오판입니다(같은 장면 관문과 같은 원칙).

**대신 막아 둔 것:** 아래 둘에 해당하는 의심은 판정을 내리지 못합니다. 이것으로 "LLM이 모든 것을 판단 불가로 만드는" 일을 억제합니다.
- 판정과 관계없는 종류의 의심
- 관계없는 카드만 인용한 의심

| 판사 판정 | 판단 불가로 내릴 수 있는 의심 |
| --- | --- |
| 편집 조작 | 같은 장소 다른 시점, 잘라내기·재압축, 날짜 오류 |
| 맥락 조작 | 날짜 오류, 다른 사건 사진, 같은 장소 다른 시점 |
| AI 생성 | 출처 기록 해석 |
| 진짜 확인 | 조작 가능성 |

| 의심 종류 | 인용 카드에 있어야 하는 신호 (`DOUBT_SIGNAL`) |
| --- | --- |
| 같은 장소 다른 시점 | 비교 카드(S, 이미지 비교, 원본 일치)에 아래 중 하나가 있어야 한다. 색 보정 관찰, 영역 밖 잔차 또는 차이 면적이 편집 국소성 한도의 절반 이상, 차이 영역 2곳 이상, 장면 유사도 0.9 미만 |
| 잘라내기·재압축 | 비교 카드에 잘라내기·반전·색 보정이 관찰되었거나, 정렬 점수가 0.95 미만 |
| 날짜 오류 | 날짜 다툼이 기록되었거나, 날짜 출처가 검색 발견일뿐이거나, 맥락·팩트체크 카드 |
| 다른 사건 사진 | 맥락 또는 팩트체크 카드 |
| 출처 기록 해석 | 강하지 않은 C2PA·워터마크 카드 |
| 조작 가능성 | 약하지 않은 조작 쪽 근거 카드 |

**신호를 요구하는 이유(실측):** 처음에는 카드 종류만 맞으면 받아들였습니다. 그러자 qwen2.5:1.5b로 돌렸을 때 이런 일이 생겼습니다.
- 변호인이 "2021-04-12 사진과 차이가 있으니 날짜 오류"라고 주장했습니다. 인용한 S1의 날짜는 다툼 없는 페이지 메타데이터였습니다.
- 배심원 3명이 모두 이 주장을 그대로 채택했습니다.
- 그 결과 올바른 편집 조작 판정이 판단 불가로 내려갔습니다.

이 사례는 회귀 테스트로 남겼습니다. 같은 의심이라도 S1에 날짜 다툼이 실제로 기록되어 있으면 판단 불가로 내려갑니다.

### 2-3. 판결문 (`Judgment`)

| 항목 | 누가 쓰나 |
| --- | --- |
| 판정과 첫 문장 | 코드. 예: "판정: 판단 불가. 판사(규칙 v3)는 '편집 조작'으로 판단했지만, 배심원이 근거 카드로 합리적 의심을 제기해 판단 불가로 낮췄어요." |
| 핵심 근거 | 서기 요약의 인용 카드. 서기 답이 무효면 코드가 고른 결정적 카드 |
| 검사·변호인 주장 요약 | 서기가 인용 조합으로 기존 공방 주장을 선택. 표시 문장은 카드 내용에서 코드가 구성. 무효면 검증된 첫 주장 |
| 남은 의심 | 서기가 기존 의심을 선택. 새 의심은 거부. 무효면 배심원의 의심 + 검증된 변호인 대안 |
| 직접 확인하는 법 | 코드. 후보 페이지를 열어 비교하기, C2PA 검증 도구, 팩트체크 원문, 원본 파일로 재검사 |

### 2-4. 프롬프트 주입 방지

- 웹 페이지에서 가져온 글은 `untrustedPageText`(최대 200자) 한 필드에만 들어갑니다. 사건 기록은 JSON으로 직렬화하고, `<`·`>`를 JSON의 `\u003c`·`\u003e`로 이스케이프합니다. 그래서 페이지 글이 `</case_file>`로 감싸기를 닫고 지시인 척할 수 없습니다.
- 지시문(system)은 저장소에 고정된 문장입니다. 페이지 글은 절대 system에 들어가지 않습니다.
- 에이전트에게는 도구가 없습니다. 함수 호출, 검색, URL 열기, 파일 쓰기가 모두 없습니다. 에이전트의 답은 실행되지 않고 문자열로만 쓰입니다.
- 에이전트 답의 링크는 `[링크 삭제]`로 바꿉니다. 화면에 보이는 URL은 카드의 URL뿐입니다. 제어 문자는 지우고, 문장은 300자로 자릅니다.
- 주입이 성공해도(예: 배심원이 "진짜 확인"이라고 답해도) 위 규칙 때문에 판정은 바뀌지 않습니다. 테스트가 이 경우를 재현합니다.
- Ollama 제공자는 loopback 주소만 받습니다. 사건 기록이 서버 밖으로 나가지 않습니다.

### 2-5. 실패 처리

- LLM이 오류를 내거나 JSON이 아니면 그 역할은 `incomplete`에 남습니다. 판정은 판사 판정 그대로입니다. 공방은 덧붙이는 층이라서, 공방이 실패했다고 판정을 바꾸지 않습니다.
- 화면에서는 "공방 미완료"로 표시합니다(설계).
- 서기 답이 무효이면 코드가 판결문을 씁니다(`clerkWritten: false`). `clerkWritten=true`는 서기의 유효한 인용 선택을 사용했다는 기존 필드이며, 자유 문장을 사실로 인정했다는 뜻이 아닙니다.
- 후속 Gemini 연결의 429/응답 오류는 예외적으로 즉시 공방을 중단하고 **맥락·법정 확인 못 함 / 판단 불가**로 끝냅니다. 재시도하지 않습니다([gemini-provider.md](gemini-provider.md)).

### 2-6. 비용과 시간

- **호출 수:**
  - 판사가 판단 불가면 0회입니다.
  - 그 외에는 6회(검사 1, 변호인 1, 배심원 3, 서기 1)를 순서대로 부릅니다. 앞 단계의 검증 결과가 다음 단계의 입력이라서 병렬로 부르지 않습니다.
- **이 서버 CPU의 최근 실측:** qwen2.5:1.5b 141.895초, 3b 232.655초, 7b 439.265초(8스레드, GPU 미사용, 동일 사례 각 1회). 초기 96/164/403초는 과거 실행입니다. [실측 비교표](llm-benchmark-2026-10-19.md), [환경·모델 크기](llm-options.md)를 참고합니다. 이번 변경에서는 모델을 재호출하지 않았습니다.
- **처리 방식:** 그래서 공방은 결과 화면과 분리한 **비동기 후처리**로 둡니다. 공방이 끝나기 전에는 판정 옆에 "공방 검토 중"을 표시합니다. 판정이 판단 불가로 내려갈 수 있다는 점도 함께 알립니다.
- **실측으로 고친 규칙 2개:** 1.5B는 근거 없는 의심을 채택했고, 7B는 변호인이 조작 쪽 논리를 냈습니다. 두 경우 모두 회귀 테스트로 남겼습니다.

### 2-7. 화면과 저장 (설계, 미구현)

- 결과 화면의 "상세 점수" 아래에 접힌 **공방 기록** 섹션을 둡니다.
  - 판결문
  - 검사·변호인 주장과 각 인용 카드(카드로 이동하는 링크)
  - 배심원 3명의 결정
  - 폐기된 주장의 수와 이유
- 판단 불가로 낮춘 경우, 판정 아래에 "판사는 ○○로 판단했지만 …"을 표시합니다. 낮추기 전 판정은 강조하지 않습니다.
- 저장: `analyses`에 `court_record jsonb`(판결문과 검증된 주장만, 폐기된 원문은 이유만), `court_model`, `court_version`을 둡니다. 공방 결과는 판정에 영향을 주므로 `pipeline_version`에 포함합니다.

## 3. 편집국 9팀 (설계만)

아래는 요약이며 부서별 현재 구현 상태·권한·인계 및 3D 표시 설계는 [newsroom-departments.md](newsroom-departments.md)에 분리했습니다. **현재 Claw3D의 7좌석은 팩트체크 부서의 법정**입니다.

| 팀 | 기존 파이프라인 단계 | 담당 | 입력 → 출력 | 권한 |

**법무 경고 예 (코드 규칙):**
- 판결문에 실존 인물 이름이 있다.
- "조작했다"처럼 행위자를 단정한다.
- 신뢰 출처 페이지 발췌를 200자 넘게 인용한다.
- 얼굴이 크게 나온 사진을 공개 링크로 만들려 한다.

경고는 표시만 합니다. 막는 것은 사람의 결정입니다.

**범위 밖 (명시)**
- **SNS 유포 추적:** 플랫폼 약관이 자동 수집을 금지합니다. 개인 계정과 게시물을 모으는 일이기도 합니다. 사용자가 직접 준 한 페이지만 확인합니다.
- **봇 계정 탐지:** 같은 이유로 하지 않습니다. 계정 단위 데이터를 수집하지 않습니다.
- 웹 전체 크롤링, 과거 기사 대량 수집, 봇 차단 우회도 하지 않습니다(기존 원칙).

## 4. LLM 제공자

- `LLMProvider` 인터페이스(`web/lib/llm/types.ts`) 하나로 분리했습니다.
- **1순위:** `OllamaProvider`(로컬, loopback만, JSON 스키마 구조화 출력, temperature 0)
- **테스트·모의 모드:** `MockLLMProvider`(역할별 스크립트). 환경 변수가 없으면 mock이며 실제 로컬 추론은 `PAIRSIGHT_LLM=ollama`로 선택합니다.
- **후속 요청으로 추가된 선택지:** GeminiProvider는 유지합니다. 원본 이미지를 보내지 않고 요약 텍스트만 사용합니다. 이번 작업에서는 외부 호출 없이 기존 실측과 공식 조건 조사만 참조합니다.
- 측정과 무료 API 조사: [llm-options.md](llm-options.md)
- 실행 예: `npx tsx scripts/court-run.ts --mock`, `npx tsx scripts/court-run.ts --model qwen2.5:7b --url http://127.0.0.1:11434`
