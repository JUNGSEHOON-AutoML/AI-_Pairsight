# LLM 선택지: 로컬 Ollama 측정과 무료 API 조사 (2026-10-19)

업데이트: 아래는 초기 조사 기록이다. 사용자 요청에 따라 텍스트 최소화 경계를 둔 Gemini 선택 제공자를 추가했다. 현재 설정·약관은 [Gemini 제공자](gemini-provider.md), 동일 사건 재측정은 [최신 벤치마크](llm-benchmark-2026-10-19.md)를 참조한다.

법정 레이어([newsroom-court.md](newsroom-court.md))의 에이전트가 쓸 LLM입니다.

**원칙**
- 무료만 씁니다.
- 판정은 코드가 합니다. LLM은 카드 ID와 정해진 의심 유형을 JSON으로 선택하고, 화면의 발언은 코드가 카드 요약에서 구성합니다.
- 1순위는 로컬 Ollama입니다. 사건 기록(사용자 주장, 페이지 발췌)이 서버 밖으로 나가지 않습니다.

## 1. 이 서버에서 Ollama

### 서버

| 항목 | 값 |
| --- | --- |
| CPU | Intel i9-10980XE, 18코어 36스레드. 측정 당시 부하 평균 약 20(다른 작업이 이미 사용 중) |
| 메모리 | 125 GB, 사용 가능 약 86 GB |
| GPU | RTX 3090 24 GB × 3. **다른 사용자의 작업이 3장 모두 100% 사용 중**(각 21–22 GB 점유) |
| 시스템 Ollama | `/usr/local/bin/ollama` 0.11.2, root 서비스로 11434 포트에서 실행 중. 모델: llama3.1:8b, phi4-mini:3.8b, gemma3:27b |

**측정 방식**
- GPU는 다른 사람의 작업에 영향을 줄 수 있어서 쓰지 않았습니다.
- 공용 서비스(11434)에도 모델을 올리지 않았습니다.
- 대신 같은 바이너리로 **CPU 전용 개인 인스턴스**를 띄웠습니다(`CUDA_VISIBLE_DEVICES=`, 127.0.0.1:11500, 모델 폴더 `~/.ollama-pairsight`).
- GPU 속도는 측정하지 않았습니다. GPU가 비는 때에 별도로 재야 합니다.
- `gemma3:4b`는 받지 못했습니다. 현재 레지스트리의 gemma3 매니페스트가 이 서버의 Ollama 0.11.2보다 새 버전을 요구합니다. 시스템 Ollama 업데이트는 관리자 권한이 필요합니다.

### 원시 속도 (CPU, temperature 0)

프롬프트는 한국어 132토큰이고, 최대 200토큰을 생성했습니다.

| 모델 (Q4_K_M) | 크기 | 스레드 | 로드 | 프롬프트 처리 | 생성 | 라이선스 |
| --- | --- | --- | --- | --- | --- | --- |
| qwen2.5:1.5b | 1.0 GB | 8 | 1.7 s | 83 tok/s | 18.3 tok/s | Apache-2.0 |
| qwen2.5:3b | 1.9 GB | 8 | 2.1 s | 41 tok/s | 12.7 tok/s | **Qwen Research License(비상업 연구용)** |
| qwen2.5:7b | 4.7 GB | 8 | 3.8 s | 20 tok/s | 6.9 tok/s | Apache-2.0 |
| qwen2.5:7b | 4.7 GB | 16 | 3.8 s | 29 tok/s | 6.7 tok/s | Apache-2.0 |

- 7B는 스레드를 16으로 늘려도 생성 속도가 그대로입니다. 메모리 대역폭이 한계라는 뜻입니다. 다른 작업과 CPU를 나눠 쓰는 서버라서 8스레드를 권합니다.
- 7B 실행 중 Ollama 러너의 메모리(RSS)는 약 5.1 GB였습니다.

### 법정 1회 (검사 → 변호인 → 배심원 3 → 서기, 6회 호출)

**입력:** `scripts/court-run.ts`로 실제 사건 기록(카드 3장, 약 1.5–2.5천 토큰)을 넣었습니다.

**사건:** `trusted_edited` fixture. 판사(규칙 v3)는 편집 조작으로 판정했습니다. 이 사례는 정답도 편집 조작입니다.

| 모델 | 6회 합계 | 호출당 | 남은 주장 (검사/변호/배심원 의심) | 폐기 | 최종 판정 |
| --- | --- | --- | --- | --- | --- |
| qwen2.5:1.5b (첫 규칙: 카드 종류만 확인) | 103 s | 17 s | 1 / 1 / 3 | 0 | **판단 불가 (잘못 낮춤)** |
| qwen2.5:1.5b | 96 s | 16 s | 1 / 0 / 0 | 5 | 편집 조작 |
| qwen2.5:3b | 164 s | 27 s | 1 / 0 / 0 | 3 | 편집 조작 |
| qwen2.5:7b | 403 s | 67 s | 2 / 1 / 0 | 1 | 편집 조작 |

**측정 조건:** 8스레드, CPU만 사용, 다른 작업이 이미 CPU의 절반 이상을 쓰는 상태였습니다.

**측정에서 드러난 점**
- **qwen2.5:1.5b:** 첫 규칙(카드 종류만 확인)에서 배심원 3명이 "차이가 있으니 날짜 오류"라는 의심을 그대로 채택했고, 올바른 편집 조작을 판단 불가로 낮췄습니다. 그래서 측정값 신호 규칙을 추가했습니다. 이후 같은 모델의 근거 없는 의심은 모두 폐기됩니다.
- **qwen2.5:7b:** 변호인이 "조작 가능성"(편집 조작을 지지하는 논리)을 대안으로 냈고, 규칙이 이를 받아들였습니다. 그래서 "변호인 대안은 판사 판정을 내릴 수 있는 의심 종류만" 규칙을 추가했습니다. 위 표의 7B 행은 이 규칙을 넣기 전 실행이고, 지금 규칙이라면 변호 대안이 0으로 폐기됩니다.
- **세 모델 모두** 이 사례(정답 편집 조작)에서 최종 판정을 바꾸지 않았습니다. 사례 1건이라서 정확도 수치가 아닙니다.

### 결론

- **CPU만으로도 동작은 합니다.** 다만 법정 1회가 분 단위라서 결과 화면에서 기다리게 할 수는 없습니다.
- 법정은 **비동기 후처리**로 둡니다. 판정은 즉시 보여주고, 공방 기록은 나중에 채웁니다. 판단 불가 결과는 공방을 열지 않으므로 호출이 0입니다.
- 비동기로 두더라도, 공방이 끝나 판정이 판단 불가로 내려가면 화면의 판정이 바뀝니다. 그래서 공방 완료 전에는 "검토 중"으로 표시하는 설계가 필요합니다(다음 작업).
- **모델:** qwen2.5:7b(Apache-2.0)를 기본으로 둡니다. 1.5B는 빠르지만 근거 없는 의심을 그대로 채택했습니다. 3B는 라이선스가 비상업 연구용이라 비영리라도 "연구"가 아닌 서비스 운영에는 쓰지 않습니다.
- GPU를 쓸 수 있으면 7B 기준 수십 배 빨라질 것으로 예상합니다. **측정하지 않은 추정입니다.**

## 2. 무료 API (조사만)

| 서비스 | 무료 한도 | 데이터 사용 | 우리 용도에 맞나 |
| --- | --- | --- | --- |
| Google Gemini API 무료 등급 | 모델별·프로젝트별 한도. 공개 문서에는 숫자가 없고 AI Studio에서 확인합니다([rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), 2026-10-15 갱신). 요금표상 Flash·Flash-Lite 계열에 무료 등급이 있고, Pro 계열에는 없습니다([pricing](https://ai.google.dev/gemini-api/docs/pricing)) | 무료 등급의 입력과 출력이 **제품 개선에 쓰이고, 사람 검토자가 읽을 수 있습니다**. 약관이 "민감하거나 기밀이거나 개인적인 정보를 보내지 말라"고 합니다. EEA·영국·스위스 사용자에게 제공하는 앱은 유료 서비스만 쓸 수 있습니다. 18세 이상만 쓸 수 있습니다([terms](https://ai.google.dev/gemini-api/terms)) | **부적합.** 사건 기록에 사용자가 쓴 주장 문장(개인정보가 들어갈 수 있음)과 제3자 기사 발췌가 들어갑니다 |
| Groq | Developer 기본 한도는 모델별로 다릅니다. 예: qwen 계열 30 RPM, 1K RPD, 200K TPD([rate limits](https://console.groq.com/docs/rate-limits)). 페이지에는 Free/Developer 탭이 있고 실제 조직 한도는 계정 Limits에서 확인하도록 되어 있어, 이 숫자를 우리 계정의 무료 한도로 보장하지 않습니다 | 서비스 약관 4.2조: 고객 입력과 출력을 학습에 쓰지 않습니다. 필요한 경우에만 보관합니다([services agreement](https://console.groq.com/docs/legal/services-agreement)) | 조건부 가능. 다만 사건 기록이 외부로 나가므로 개인정보 고지가 필요합니다. 한도가 시범 운영 규모에 맞는지 확인해야 합니다 |
| OpenRouter `:free` 모델 | 무료 모델은 분당/일별 제한이 있으며 누적 크레딧 구매에 따라 구간이 달라집니다. 공식 페이지의 숫자 표가 이번 문서 조회에서 비어 있어 이전 제3자 수치를 현재 한도로 사용하지 않습니다. 실제 일일 한도는 인증된 `GET /api/v1/key`로 확인하는 구조이며 이번에는 계정 조회를 하지 않았습니다([limits](https://openrouter.ai/docs/api_reference/limits)) | 실제로 처리하는 제공자마다 정책이 다릅니다. 무료 모델 중에는 입력을 기록·학습에 쓰는 곳이 있습니다 | 현재 미선택. 실제 무료 한도와 경유 제공자별 데이터 정책을 추가 확인해야 합니다 |

**결론:** 로컬 Ollama를 유지합니다. 무료 API는 대안으로만 기록합니다. 쓰게 되면 `LLMProvider` 구현 하나를 추가하면 되고, 개인정보 고지와 사건 기록 최소화(주장 문장 제외 등)가 먼저 필요합니다.

## 편집국 설계 재확인 (2026-10-19)

- 현재 읽기 전용 자원 확인: 논리 CPU 36개, 메모리 총 125.5 GiB / 가용 72.3 GiB. RTX 3090 24 GiB 3장 모두 사용률 100%, 각각 약 12.0 / 19.1 / 20.4 GiB 사용 중이었습니다. 다른 사람의 작업을 중지하거나 공용 GPU에 모델을 올리지 않았습니다.
- 최신 동일 사건 측정은 1.5B **141.895초**, 3B **232.655초**, 7B **439.265초**이며 각각 6회 호출입니다. 이 수치는 이번 카드 기반 발언 제한 보완 전 측정이며, 현재 버전의 성능·정확도 실측이 아닙니다. 원시 생성 속도·모델 크기도 위 초기 측정값입니다. 부서 설계 작업에서는 추가 로컬/외부 추론을 실행하지 않았습니다.
- Gemini 공식 [한도](https://ai.google.dev/gemini-api/docs/rate-limits)와 [데이터 사용 약관](https://ai.google.dev/gemini-api/terms)을 다시 확인했습니다. 한도는 프로젝트별 RPM/입력 TPM/RPD이며 실제 수치는 AI Studio 계정에서 확인해야 합니다. 무료 입력/출력은 개선·사람 검토 대상이 될 수 있습니다. 계정의 실제 무료 등급이나 과금 상태는 확인하지 못했습니다.
- 운영 우선순위는 Ollama, 안전한 시연 기본값은 mock입니다. 이후 사용자가 요청해 이미 구현한 Gemini를 제거하지 않았고, 이번에는 호출하지 않았습니다. 인물·날짜 등 새 사실이 자유 문장에 섞이지 않도록 법정의 발언 표시를 카드 기반으로 보완했습니다.
