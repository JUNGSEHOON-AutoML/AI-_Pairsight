# Case 중심 편집국 통합 — 2026-10-19

실제 사건 하나를 부서별 워커가 순서대로 처리하며, 같은 Case에 섹션을 누적한다. 기존 이미지 비교·판정 v3·법정 코드를 호출한다. 비영리 시범 운영이며 결제·유료 API 자동 전환은 없다. 원본 checkout은 보존하고 Pairsight와 Claw3D 각각 별도 worktree에서 구현했다.

## 상태와 저장

접수 → 모니터링 → OSINT → AI&데이터 → 보안&봇 → 팩트체크 법정 → 법무 → T&S → 홍보&리포팅 → 미디어 리터러시 → 완료.

순차 처리 부서는 9개다. 신뢰성 분석은 별도의 관찰자로 모든 단계를 감시한다. 이전 문서의 ‘모니터링/AI 탐지’는 분류와 계산으로 나누고, 신뢰성은 처리 순서에서 제외했다.

Case에는 입력, 단계, 상태, revision, 실행 소유권, 부서별 기록, 사람 승인, 사람 평가 라벨이 있다. 섹션에는 시작·종료·소요 시간·시도 횟수·출력·고정 오류 코드가 있다. 작업 도중 실패하면 해당 섹션에서 멈추고 실패 이벤트를 남긴다. 운영자의 명시적 재시작만 실패 단계부터 재개한다. 프로세스가 사라진 경우 lease 만료를 감지해 실패로 남긴다. 다음 단계로 조용히 넘어가지 않는다.

시범 운영 저장소는 Node 24의 SQLite다. `web/.newsroom/cases.sqlite`에 트랜잭션으로 Case와 이벤트를 함께 저장한다. 디렉터리 0700, DB 0600, Git 제외. 서버와 워커 프로세스가 같은 파일을 사용한다. Supabase 연결이나 클라우드 RLS 실행을 완료한 것으로 간주하지 않는다. 기존 SQL/RLS는 이후 이관용 설계이며 현재 접근 제어는 운영자 세션과 서버 코드가 담당한다.

## 입력·발견·검증 범위

- 운영자 수동 접수: 이미지 또는 공개 기사 URL, 주장 200자, 사건 날짜, 원본 후보 페이지 최대 5개, 제보 경로와 권리/콘텐츠 플래그.
- URL의 대표 이미지가 유포 사진과 같다고 가정하지 않는다. 운영자가 기사 내 이미지 URL을 지정하거나 이미지를 직접 제출하지 않으면 코드가 판단 불가를 유지한다.
- Google Fact Check `claims:search`, `languageCode=ko`는 운영자 내부 피드다. 조회된 항목을 사건으로 접수한다. 타 기관의 평가를 Pairsight 판정으로 복사하지 않는다.
- 이번 통합 흐름의 발견 경로는 운영자 후보와 Fact Check 텍스트 검색이다. TinEye/Google Vision 역검색, Fact Check `claims:imageSearch`, Supabase 임시 URL은 연결하지 않았다. 기존 인터페이스와 mock 시험은 유지한다.
- 기존 RSS 이미지 색인은 새 Case 워커에서 호출하지 않는다. 웹 전체 크롤링·자체 색인·SNS 수집은 하지 않는다.
- 후보는 기존 PolicyFetch와 OnDemandCandidateVerifier로 검증한다. robots 허용을 확인하지 못하거나 차단·유료벽이 있으면 중단한다. 같은 출처 요청은 최소 1초 간격이며 더 긴 Crawl-delay를 따른다.
- 장면 관문, 편집 국소성, 기존 실제 사진/합성 반례 기준값은 변경하지 않았다. 썸네일로 미세 편집을 확정하지 않으며 페이지 게시일을 이미지 촬영일로 쓰지 않는다.
- 출처 URL·날짜·해시·512px 이하 썸네일·최대 200자 발췌만 유지한다. 기사 전문·고해상도 원본은 저장하지 않는다. 피드의 주장/매체/평가 텍스트는 같은 페이지의 발췌 예산에서 차감한다. HTML은 메모리에서 추출·지시문 검사 후 버린다.

## 법정과 승인

실제 사건은 기본 Ollama를 사용하고 mock 실행을 거부한다. 테스트는 명시적 allowTestProviders로만 mock을 주입한다. 판단 불가이면 공방을 생략해 LLM 호출 0회다. 제공자 오류·429·사용 불가이면 법정 단계에서 실패하고 ‘맥락·법정 확인 못 함’과 실제 호출 수를 남긴다. 자동 재시도는 없다.

LLM에는 도구를 주지 않는다. 인용 없는 주장, 근거에 없는 사실, 판정 상향은 기존 법정 코드가 거부한다. 저장되는 발언은 근거 카드에서 코드가 구성한 내용이며 폐기된 원문은 보관하지 않는다. 법정의 대기·작업·발언 이벤트를 Case 이벤트로 기록한다.

승인자는 HTTP 본문이 아닌 서버 세션에서 정한다. 화면에서 본 revision과 다르면 승인 요청을 거부한다. 최초 검토자가 사실 제목과 200자 공개 요약을 정하며 정치 사건의 두 번째 검토자는 같은 내용을 검토한다. 성적 콘텐츠·미성년자·사생활 플래그는 승인할 수 없다. 공개 이미지 권한 미확인, 선거 기간, 잔혹 장면이면 이미지를 게재하지 않는다.

승인 뒤 두 마지막 워커가 완료돼야 공개 저장소에 나타난다. 승인 대기/반려/실패/철회/fixture는 제외한다. 공개 상세는 기존 2D 공방 타임라인과 근거 카드다. 정치·선거 추가 규칙은 [category-policy.md](category-policy.md)를 따른다.

## 운영자 화면과 권한

- `/newsroom`: 한 화면의 왼쪽 카테고리 대시보드 + 오른쪽 실시간 3D 편집국. 전체 사건/승인 대기/공개 사례 탭, 조작 유형·제보 경로 필터, 부서 선택·작업 기록, 신뢰성 지표와 Google 피드.
- `/newsroom/new`: 이미지/URL 수동 접수.
- `/newsroom/[id]`: 모든 부서 기록, 썸네일·히트맵, 날짜·근거·법정, 재시작·승인·반려·철회·평가 라벨.
- `/newsroom/login`: 별도 운영자 계정. 기존 시연 로그인 링크를 운영자 권한으로 인정하지 않는다.
- `/cases`: 승인된 실제 Case만. 기존 가상 공개 seed는 테스트에서 명시적으로 주입하는 용도로만 사용한다.
- 기존 시연 검사·계정·기록은 `/dev` 아래로 이동했다. 프로덕션에서 이 페이지들은 비노출이다.

비밀번호는 터미널 getpass로 입력받아 salt+scrypt 해시만 파일에 저장한다. 세션은 임의 토큰의 SHA-256을 DB에 저장하고 HttpOnly/SameSite=Strict 쿠키로 8시간 유지한다. 로그인 실패 5회/15분 제한, 변경 요청 Origin/Host·전용 헤더 확인, 사용자 삭제 시 세션 무효화가 있다. 파일 계정은 localhost 시범 운영용이며 공개 운영용 조직 SSO/RBAC를 구현한 것은 아니다.

## Claw3D

Claw3D는 별도 worktree·프로세스로 유지하고, 화면은 Pairsight `/newsroom` 안에 합쳤다. 왼쪽 사건을 선택하면 오른쪽 3D의 해당 부서를 강조하고, 사건이 이동하면 선택 부서도 따라간다. 3D 구역을 클릭하면 같은 화면의 해당 부서 기록으로 바뀐다. 390px에서는 주제가 가로 탭으로 바뀌고 사건 목록과 3D를 위아래로 배치한다.

`GET /api/operator/live`는 인증된 운영자에게만 SSE를 보낸다. SQLite 변경을 500ms마다 확인하되 변경된 경우에만 요약 스냅샷을 내보낸다. 이벤트가 없는 revision 변경도 잡는다. 10초 heartbeat, 세션 취소/만료 시 즉시 전송 종료, 연결 오류·heartbeat 20초 미수신 시 마지막 기록 표시와 작업 애니메이션 중지가 있다. 실제 반영 지연은 DB 조회 간격에 네트워크·브라우저 렌더링 시간을 더한 값이다.

실제 `running` 상태에서 담당자가 휴식 위치에서 책상으로 걸어가 타이핑한다. 부서 간 Case 상태 변화는 문서 인계 동작으로 표시한다. 새로 열거나 재연결할 때 지난 이력을 진행 중인 작업처럼 재생하지 않는다. 대기·실패·승인 대기는 작업 동작을 켜지 않는다. 서버의 짧은 단계가 조회 사이에 끝나면 작업 애니메이션이 생략될 수 있으며 모든 단계의 이벤트는 작업 기록에서 확인한다. 근거 ID가 있는 법정 발언만 말풍선에 표시한다. 이 3D 움직임은 워커 상태의 시각화이며 별도의 자율 에이전트 실행을 추가한 것은 아니다.

Pairsight HTTP 어댑터는 기존 custom-runtime 형태의 `GET /state`, `GET /registry`와 `GET /events`, `GET /health`를 제공한다. Bearer 토큰 인증이며 127.0.0.1에만 바인딩한다. 모든 변경 메서드는 405다. 이 토큰은 서버 환경 변수로만 전달되고 브라우저·설정 파일·로그에 쓰지 않는다.

Claw3D의 별도 `server/newsroom.js`는 원래 OpenClaw/Hermes 실행 경로를 로드하지 않는다. 127.0.0.1 전용, localhost Host 확인, 읽기 경로 허용 목록, 교차 출처 차단, 쓰기 메서드 차단을 적용했다. 통합 화면은 `/controlroom/newsroom` iframe을 사용한다. Pairsight의 인증 프록시가 고정된 localhost 뷰어의 HTML과 `/_next/static` 자산만 전달한다. 임의 URL, API·설정·변경 요청은 전달하지 않는다. 클라이언트 쿠키·API 키·토큰도 뷰어에 전달하지 않는다. Claw3D 빌드의 `CLAW3D_NEWSROOM_MODE=1`은 `/controlroom` basePath를 설정해 포트 포워딩된 브라우저에서도 하나의 출처로 로드되게 한다. CSP frame-ancestors self와 SAMEORIGIN을 유지한다.

부모 화면이 같은 SSE에서 받은 제한된 관제 스냅샷을 iframe에 전달한다. 양쪽에서 postMessage의 origin과 source를 검증하며 뷰어가 내보내는 명령은 부서 선택뿐이다. 입력 이미지·원문 주장·운영자 신원은 3D 전송에서 제외한다. 독립적인 localhost 뷰어를 진단용으로 여는 경우에만 기존 `/controlroom/api/newsroom` 2초 조회를 사용한다. 일반 사용에는 별도 탭이나 3D 주소가 필요 없다.

사용자가 여는 주소는 **Pairsight 3002의 `/newsroom` 하나**다. 내부 기본 포트: Pairsight 3002 / Claw3D 3460 / HTTP 어댑터 3461. 기존 3000과 충돌하지 않는다. 실제 서버는 fixture 사건을 내보내지 않는다. 이전 7좌석 mock 반복 시연은 새 실행기에서 호출하지 않는다.

## 외부 API·RSS 확인

2026-10-19, 새 키로 한국어 ‘사진’ 검색이 HTTP 200으로 성공했다. 처음 3개 결과 확인 후 피드 조회로 최대 10건을 읽고 3건을 비공개 접수했다. 결제 등록/설정 변경은 하지 않았다. 프로젝트의 기존 결제 연결 여부를 직접 감사한 것은 아니며 향후 무과금을 보장하지 않는다.

[Google 공식 시작 안내](https://developers.google.com/fact-check/tools/api)는 Claim Search에 API 키를 요구한다. [API 약관](https://developers.google.com/fact-check/tools/api/terms)은 Google API 이용약관 적용을 명시한다. 이번 확인에서 계정별 공식 할당량이나 별도 무제한 무료 보장은 확인하지 않았다. 앱 자체 제한은 서비스 전체 6회/시간, 같은 검색어 15분 캐시, 자동 페이지 넘김·429 재시도 없음이다. 이 숫자는 Google의 공식 한도가 아니다.

비영리라는 이유로 RSS의 조직 내 이용이 자동 허용된다고 가정하지 않는다. [연합뉴스의 2026-03-16 저작권 고지](https://www.yna.co.kr/amp/view/AKR20260316085000011)는 무단 복사·배포 및 AI 활용을 제한한다. [한겨레의 RSS 안내](https://notice.hani.co.kr/customer_view.html?bid=notification&no=333&page=40)도 조직의 자동 수집·내부 재이용에 대한 충분한 허락 근거로 보지 않았다. **현재 언론사 RSS 연결은 모두 비활성**이다. 허락이 확인되면 운영자 내부에 제목·링크·게시일만 추가하고 공개 결과에는 RSS 항목을 노출하지 않는다. 언론사에 승인 요청 메시지를 보내지는 않았다.
