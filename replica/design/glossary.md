# Pairsight 용어집

모든 화면 문구, 코드 상수, 공유 페이지, 고지문은 이 표의 표기를 그대로 씁니다. 같은 뜻을 다른 말로 쓰지 않습니다.
코드 값(영문)은 DB의 `analyses.verdict`, `evidence.kind`, `evidence.strength`와 1:1로 맞춥니다.

## 판정 (5종)

| 화면 표기 | 코드 값 | 한 줄 정의 | 아이콘 (Lucide) | 색 역할 |
| --- | --- | --- | --- | --- |
| **진짜 확인** | `authentic` | 원본 일치나 출처 증명(C2PA)으로 이 이미지가 실제 촬영본임을 확인함 | `badge-check` | `verdict-real` |
| **AI 생성** | `ai_generated` | 이미지 전체가 AI로 만들어졌다는 강한 근거가 있음 | `bot` | `verdict-ai` |
| **편집 조작** | `edited` | 실제 사진의 일부를 바꾸거나 합성했다는 근거가 있음 (원본과 달라진 곳이 있음) | `scissors` | `verdict-edited` |
| **맥락 조작** | `miscontextualized` | 사진 자체는 진짜지만, 다른 시점이나 다른 사건의 사진으로 쓰였다는 근거가 있음 | `calendar-x` | `verdict-context` |
| **판단 불가** | `inconclusive` | 결론을 내릴 만큼 강한 근거가 없음. 진짜라는 뜻도, 가짜라는 뜻도 아님 | `circle-help` | `verdict-unsure` |

규칙:

- 판정 이름은 항상 **아이콘 + 글자**로 함께 표시합니다. 색만으로 구분하지 않습니다.
- "가짜", "거짓", "진짜일 확률" 같은 말은 판정 이름으로 쓰지 않습니다. 사용자가 "가짜인가요?"라고 물어도 화면은 위 5개 이름으로 답합니다.
- 판정에는 항상 **한 줄 이유**가 붙습니다. 예: "같은 사진이 2019년 기사에 먼저 실렸어요."

## 근거

| 화면 표기 | 코드 값 (`evidence.kind`) | 뜻 | 기본 강도 |
| --- | --- | --- | --- |
| **원본 일치** | `source_match` | 같은 이미지가 다른 곳에 먼저 있었음 | 강 (날짜가 확인될 때) / 중 (날짜가 없을 때) |
| **출처 증명 (C2PA)** | `c2pa` | 파일 안의 서명된 생성·편집 기록 | 강 (서명이 유효할 때) |
| **워터마크** | `watermark` | AI 생성 도구가 넣은 보이지 않는 표식 | 강 (높은 신뢰도) / 중 |
| **팩트체크 기록** | `fact_check` | 언론·팩트체크 기관이 이 이미지를 이미 검증함 | 강 |
| **촬영 정보 (EXIF)** | `exif` | 카메라 기종, 편집 프로그램 흔적 | 약 (쉽게 지우거나 바꿀 수 있음) |
| **AI 탐지** | `pixel_model` | 픽셀 패턴을 본 탐지 모델의 점수 | **항상 약.** 혼자서 판정을 결정하지 않음 |
| **화면 재촬영** | `screen_recapture` | 모니터를 다시 찍은 사진인지 | 약 |

### 근거 강도 배지 (하나로 통일)

| 표기 | 코드 값 | 뜻 | 표시 |
| --- | --- | --- | --- |
| **강** | `strong` | 혼자서도 판정을 결정할 수 있음 | 막대 3칸 + "강" |
| **중** | `medium` | 다른 근거와 함께일 때만 판정에 쓰임 | 막대 2칸 + "중" |
| **약** | `weak` | 참고용. 판정을 바꾸지 않음 | 막대 1칸 + "약" |

모든 근거 카드에 이 배지 하나만 씁니다. 퍼센트, 별점, 신호등 같은 다른 강도 표시는 쓰지 않습니다.

### 근거의 결과 (카드 안의 상태)

| 화면 표기 | 코드 값 (`evidence.outcome`) |
| --- | --- |
| 진짜 쪽 근거 | `supports_real` |
| 조작 쪽 근거 | `supports_manipulated` |
| 영향 없음 | `neutral` |
| 확인 못 함 | `unavailable` |

## 날짜

| 화면 표기 | 뜻 | 금지 표현 |
| --- | --- | --- |
| **TinEye가 처음 발견한 날짜** | TinEye 크롤러가 이 이미지를 처음 본 날. 실제 게시일은 더 이를 수 있음 | ~~최초 게시일~~, ~~처음 올라온 날~~ |
| **페이지에 적힌 게시일** | 원본 페이지의 메타데이터(`datePublished` 등)에 적힌 날. 사이트가 바꿀 수 있음 | ~~공식 게시일~~ |
| **확인 시각** | Pairsight가 이 분석을 마친 시각. 모든 결과 화면에 표시 | ~~업데이트 시간~~ |

날짜 옆에는 항상 출처를 함께 적습니다. 예: "2019-03-02 · TinEye가 처음 발견한 날짜 (실제 게시일은 더 이를 수 있음)"

## 상태와 동작

| 화면 표기 | 뜻 |
| --- | --- |
| **원본 없음** | 다른 곳에서 같은 이미지를 찾지 못함. 판정이 아니라 상태입니다. "원본이 없다 = 가짜"가 아님 |
| **분석 중** | 근거를 모으는 중 |
| **분석 실패** | 시스템 오류로 끝내지 못함. 무료 횟수는 차감하지 않음 |
| **무료 횟수** | 하루에 무료로 할 수 있는 검사 수. "크레딧", "토큰"이라고 부르지 않음 |
| **재검사** | 같은 이미지를 최신 검색 결과로 다시 분석함 |
| **검사** | 사용자가 이미지 하나를 넣고 결과를 받는 한 번의 행위. "스캔", "분석 요청"이라고 부르지 않음 |

## 범위 (MVP)

- **포함:** 이미지 파일 업로드, URL을 넣으면 그 페이지의 이미지를 추출해 검사
- **제외:** 기사 본문의 사실 확인(주장 추출, 팩트체크 매칭). URL 결과 화면에 "기사 내용이 사실인지는 확인하지 않아요. 이미지만 확인해요."라고 항상 표시합니다.

## DB 반영

[schema.sql](../schema.sql)에 반영했습니다(2026-10-18).

- `analyses.verdict`는 위 5개 코드 값만 받습니다.
- `evidence.strength`는 `strong | medium | weak`만 받습니다.
- `pixel_model`은 DB 제약으로 항상 `weak`입니다.
