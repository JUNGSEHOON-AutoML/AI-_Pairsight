# 동일 사건의 Ollama/Gemini 재판 비교

2026-10-19, `web/scripts/court-run.ts`의 기존 `trusted_edited` 사례를 다시 실행했다. 실제 로컬 이미지 비교 + 가상 후보 페이지로 얻은 카드로 재판한다. 정답과 코드 판정은 모두 **편집 조작**이다. 총 시간은 입력 분석 이후 `runCourt` 시작부터 종료까지이며 모델 로딩 시간은 포함한다.

| 제공자 | 이번 실측 시간 | 호출 수 | 최종 판정 | 검사 / 변호 대안 / 배심원 의심 | 폐기 | 상태 |
| --- | ---: | ---: | --- | --- | ---: | --- |
| Ollama qwen2.5:1.5b | 141.895초 | 6 | 편집 조작 | 1 / 0 / 0 | 5 | 완료 |
| Ollama qwen2.5:3b | 232.655초 | 6 | 편집 조작 | 1 / 0 / 0 | 3 | 완료 |
| Ollama qwen2.5:7b | 439.265초 | 6 | 편집 조작 | 2 / 0 / 0 | 3 | 완료 |
| Gemini gemini-3.8-flash | 42.526초 | 6 | 편집 조작 | 3 / 1 / 0 | 2 | 완료 |

Gemini는 사용자가 숨김 입력 도구로 키를 저장한 뒤 실제 API로 1회 측정했다. 6회 모두 완료했고 재시도는 없었다. 원래 코드 판정과 최종 판정은 모두 편집 조작이며 서기 작성도 완료했다. 카드 요약 텍스트만 전송했다. 보고서에는 시간·호출 수·검증 통과/폐기 개수 등 요약만 남겼고 원시 응답 임시 파일은 측정 후 삭제했다. 이번 1회에서는 Gemini 시간이 가장 짧았지만 일반적인 속도나 정확도 우열을 뜻하지 않는다.

Ollama 0.11.2, CPU 전용 개인 인스턴스(127.0.0.1:11500), 모델별 8스레드, 1회씩 순차 실행했다. 공용 인스턴스와 GPU는 사용하지 않았다. 여러 작업이 실행되는 공유 서버이고 이 작업의 검증도 일부 겹쳤으므로 시간 차이는 모델 크기만의 효과가 아니다. 같은 규칙과 사건을 사용했으나 Gemini는 외부 전송 최소화를 위해 기사 발췌·URL 등을 제거하고 최대 출력 토큰 설정도 다르다. Gemini는 외부 API의 네트워크 왕복을 포함하고 Ollama는 로컬 CPU 추론이다. 동일 프롬프트/토큰 예산/하드웨어의 엄밀한 성능 비교는 아니다.

기존 조사 시각의 96/164/403초와 이번 값은 별도 실행이다. 최신 표에 기존 측정값을 섞지 않았다. 사례 1건이므로 네 모델의 일반 정확도를 뜻하지 않는다. 3B는 앞선 라이선스 조사대로 연구 비교용으로만 사용하고 운영 모델로 바꾸지 않았다.
