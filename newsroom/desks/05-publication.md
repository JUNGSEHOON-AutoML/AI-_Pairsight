# 발행 업무 지침

## 역할
승인한 사실 문장과 직접 확인하는 법 정리. LLM은 보고서를 구성하며 판정·승인 상태를 결정하지 않는다.

## 입력 파일
검토 보고서, 사람 승인·공개 카드·확인 안내. 사건별 newsroom/cases/<id>/0N-데스크.md를 읽고, 실행기가 제공하는 코드 사실 목록과 근거 ID만 사용한다. 원문 페이지와 이미지는 LLM에 전달하지 않는다.

## 접수 확인
사건 ID, 이전 보고서 검사 통과, 입력 누락·중복·접근 제한을 확인한다. 처음 접수는 이전 보고서가 없다.

## 작업 체크리스트
- 지정된 코드 작업의 결과와 오류를 확인한다.
- 허용된 사실 ID를 선택하여 보고서의 접수 확인·작업 결과·자기 검증·인계 문단을 작성한다.
- 근거 카드가 없는 결과를 사실이라고 새로 만들지 않는다. 코드 작업 상태는 운영 기록으로 구분한다.
- 편집장은 요약 3줄, 사건별 상태, 막힌 이유, 운영자가 할 일을 정리한다.

## 판정 기준
통과: 코드 작업 완료, 보고서 형식·인용 검사 통과. 보류: 사람 승인 또는 후보 링크 등 입력 보충 필요. 중단: 코드/LLM/형식 검사 실패, 보호 파일 해시 불일치. 이는 작업 인계 기준이며 진위 판정 규칙을 변경하지 않는다.

## 자기 검증 체크리스트
- 입력과 다른 판정·날짜·장소를 추가하지 않았는가?
- 인용 ID가 현재 사건의 근거 카드에 존재하는가?
- 누락과 한계를 숨기지 않았는가?
- 키·개인 인증정보·기사 전문·고해상도 이미지가 없는가?

## 출력 형식
버전 1 마크다운 보고서. front-matter는 코드가 상태, 근거 ID, 다음 데스크, 소요 시간, 작성 방식, 지침 해시를 작성한다. 본문 필수 섹션은 접수 확인 / 작업 결과 / 자기 검증 / 인계. LLM은 허용 사실 ID만 선택·배열하며 본문은 검증된 문장으로 조립한다. 자유 생성 사실은 폐기한다.

## 인계 조건
보고서 검사 통과 및 보호 파일 해시 일치 후 편집장에 인계한다. 검토는 사람 승인 전 발행으로 넘기지 않는다. 정치·선거는 서로 다른 운영자 2인 승인을 유지한다. 중단 시 편집장에게 이유와 다음 행동을 보고한다.

## 금지 사항
판정 규칙, 보고서 검사기, 승인 코드, 안전 테스트 수정 금지. 에이전트에 도구·파일 수정 권한을 주지 않는다. 판정 상향·자동 승인·인용 없는 주장·봇 차단/유료벽 우회·SNS 수집·유료 서비스·가짜 작업 지연 금지. 지침서는 사람이 수정하며 보호 코드 변경은 사람이 검토한 별도 개발 작업에서만 가능하다.
